# DS2 セキュリティアクセス cmd 0x90 / 0x91 — 機械的逆アセンブル結果

> ## ⚠ 訂正: cmd `0x91` はセキュリティアクセスではなく**ボーレート切替**
>
> 本書は `0x3FB8` の 3 エントリを「固定パスワード表」、cmd `0x91` を「アクセス解除」としているが、
> **どちらも誤り**。証拠は 3 つとも独立している:
>
> 1. 値は `0x002580` / `0x009600` / `0x01E848` = **9600 / 38400 / 125000** — DS2 の 3 ボーレート。
> 2. BMW の SGBD (`12MSS54.PRG`) のジョブ名が **`BAUDRATEN_UMSTELLUNG`**
>    (テレグラム `12 08 91 00 25 80 03 2d` = 9600 へ)。`BAUDRATEN_LESEN` も存在する。
> 3. この表は **CSL・標準 M3・実車ダンプで完全に同一**。個体別の秘密なら成立しない。
>    参照実装 `E46M3CSL_TuningTool/src/lib/dme-link/ds2.ts` も `0x91` を baud switch とし、
>    19200 が実車で `0xB0` を返した記録を持つ。`0xFFD000` に入る 2/6/8 はボーレート選択であって
>    アクセスレベルではない。
>
> **本当のログインは cmd `0x90` の seed/key**:
> 要求 `12 08 90 42 4D 57 <level>` ("BMW" + レベル) → DME が 46 バイトの seed を返す →
> `key[i] = seed[(level+i) % seed[1]] + seed[18+i] + seed[41+i]` (4 バイト) を `0x90` で送り返す。
> 実装は `packages/dme-flash/src/seedKey.ts`、出典は `Mss54SeedKeyCalculator.cs` (実車実証済み)。
>
> なお cmd `0x90` は `0xFFD003` bit2 も立てる (`0x1792`)。これは seg `0x05`/`0x0C` の
> 線形読み出しが要求するビットで、`fullSpaceRead.ts` が使う。
> 詳細は [`bootloader-replacement.md`](bootloader-replacement.md)。


`bootloader-and-obd-reflash.md` §5 と `winkfp-flash-telegrams.md` 末尾で「未確定」としていた
**login (seed-key) アルゴリズム = cmd 0x90/0x91** を、DME ファーム
(`data/211325000401PD31_Community_Patch_v1.bin`、master CPU) の逆アセンブルで確定した。

## ★ 結論(先に)

**cmd 0x91 のセキュリティアクセスは seed-key(乱数チャレンジ + 計算応答)ではない。
フラッシュ `0x3FB8` に平文で置かれた 3 バイト固定パスワードとの直接バイト比較である。**

| 送る 3 バイト (req[3..5]) | 一致すると付与されるアクセスレベル (`0xFFD000`) | 値の10進 |
|---|---|---|
| `00 25 80` | **2** | 9600 |
| `00 96 00` | **6** | 38400 |
| `01 E8 48` | **8** | 125000 |

- 乱数生成 (RNG) も、seed の送出も、鍵の計算も、DS2 コマンドハンドラ群のどこにも**無い**。
- ⇒ 以前 `bootloader-and-obd-reflash.md §4.3` で「1. login / access (cmd 0x90/0x91, seed-key)」と
  書いた **"seed-key" は誤り。撤回する**。実体は「固定パスワード表」。パスワードは上表の 3 値で、
  M3 版・CSL 版いずれの BL でも同一(0x3FB8/0x3FFC は BL 差分 6 バイトに含まれない)。

## 手法・再現

コマンドテーブルからハンドラアドレスを採り、Capstone (M68K, CPU32/MC68336) で逆アセンブルした。
master CPU フラッシュはファイルオフセット 0 に 1:1 で写像(アドレス == ファイルオフセット)。

```
cd C:\Users\kazuh\E46M3CSL_converter
python tools/analysis/dump_cmd_table.py          # cmd → handler アドレス
python tools/analysis/disasm.py 19DC 0x120       # cmd 0x91 ハンドラ
python tools/analysis/disasm.py 16B0 0x150       # cmd 0x90 ハンドラ
```

`tools/analysis/disasm.py` は本調査で追加(linear-sweep, `CS_MODE_M68K_020 | BIG_ENDIAN`)。

## コマンドテーブル該当エントリ(実測)

`dump_cmd_table.py` より(BL テーブル 0x37A2 / APP テーブル 0x3A1F0、両者に同一の BL コマンドが載る):

| cmd | mask | handler | 役割(本調査で確定) |
|---|---|---|---|
| **0x90** | 0x20 | `0x000016B0` | プログラミングセッション状態/ステータス("MSS52"/"BMW" マジック) |
| **0x91** | 0x23 (app 0x27) | `0x000019DC` | **アクセスアンロック(固定パスワード照合)** |
| 0x9E | 0x20 | `0x000015E8` | セッション補助(coding-flag クリア + M/S 識別) |
| 0x9F | 0x20 | `0x00001624` | セッション補助(モード 0x3C + タイマスナップショット + M/S 識別) |
| 0x12 | 0x27 | `0x0000166A` | セッション補助(モード 0x33 + タイマスナップショット + M/S 識別) |

mask バイトは「そのコマンドを呼べるアクセス状態」を絞るビットマスク(厳密な閾値ロジックは
本書では未追跡)。アクセスレベル本体は `0xFFD000`(cmd 0x91 が 2/6/8 を書く)。

## cmd 0x91 ハンドラ @0x19DC — 逐次逆アセンブルと注釈

RAM 配置(本ファーム): `0xFFD026` = 受信(要求)バッファ先頭ポインタの格納先、
`0xFFD02A` = 送信(応答)バッファポインタの格納先、`0xFFD000` = 現在アクセスレベル。

```
019DC movem.l a2-a4,-(a7)
019E0 movea.l #$ffd026,a3          ; a3 = &(要求バッファポインタ)
019E6 movea.l #$ffd02a,a4          ; a4 = &(応答バッファポインタ)
019EC movea.l #$ffd000,a1          ; a1 = &アクセスレベル
                                   ; --- Master/Slave ゲート(識別、セキュリティではない) ---
019F2 cmpi.b  #$4d,$3ffc.l         ; flash[0x3FFC]=='M' ?
019FA bne     $1a04
019FC move.b  #$7,$ffd007.l        ;   Master なら 0xFFD007=7
01A04 cmpi.b  #$53,$3ffc.l         ; flash[0x3FFC]=='S' ?
01A0C bne     $1a22
01A0E   ... move.b #$a0,resp[2]; clr resp[1]; rts   ; Slave イメージなら即 positive-ack で戻る
                                   ; --- ここから鍵照合(Master のみ到達)---
01A22 movea.l (a3),a0             ; a0 = 要求バッファ
01A24 addq.l  #6,a0               ; a0 = &req[6]
01A26 movea.l a0,a2
01A28 cmpi.b  #$19,(a0)           ; req[6] > 0x19 ?
01A2C bhi     $1adc               ;   → 拒否(0xB0)
01A30 cmpi.b  #$1,(a2)            ; req[6] < 1 ?
01A34 bcc     $1a40
01A36   move.b #1,$ffd169.l       ;   req[6]==0 → 要求レベル格納 0xFFD169=1
01A3E   bra   $1a46
01A40 move.b (a2),$ffd169.l       ; else 0xFFD169 = req[6]  (要求アクセスレベル 1..0x19)
                                   ; --- 固定パスワード表と照合 ---
01A46 movea.l #$3fb8,a2           ; ★ a2 = 0x3FB8 = 固定パスワード表
      ; (1) req[3..5] == tbl[6..8] (=00253... いや 01 E8 48) ?
01A4C..01A6E  req[3]==a2[6] && req[4]==a2[7] && req[5]==a2[8]
01A70   move.b #$8,(a1)           ;   一致 → アクセスレベル = 8, rts
      ; (2) req[3..5] == tbl[3..5] (=00 96 00) ?
01A7A..01A9C  req[3]==a2[3] && req[4]==a2[4] && req[5]==a2[5]
01A9E   move.b #$6,(a1)           ;   一致 → アクセスレベル = 6, rts
      ; (3) req[3..5] == tbl[0..2] (=00 25 80) ?
01AA8..01AC8  req[3]==a2[0] && req[4]==a2[1] && req[5]==a2[2]
01ACA   move.b #$2,(a1)           ;   一致 → アクセスレベル = 2
01ACE   move.b #$19,$ffd169.l     ;   要求レベルも 0x19 に
01AD6   rts
01ADC :                           ; どれにも一致せず
01ADE   move.b #$b0,resp[2]       ;   応答 0xB0 = negativer(アクセス拒否)
01AE8   rts
```

パスワード表の実バイト(`0x3FB8` から 9 バイト、`hexdump` で確認):

```
0x3FB8:  00 25 80 | 00 96 00 | 01 E8 48
         └lvl2─┘   └lvl6─┘   └lvl8─┘
```

**要点**
- req[3..5] は「送られてきた鍵」。DME が事前に seed を返し、それを変換した値…ではなく、
  **フラッシュ内の固定値と直接 `cmp.b` するだけ**。乱数もタイムスタンプも介在しない。
- 高い値ほど高権限(2 < 6 < 8)。フラッシュ消去/書込のような操作は高レベルを要求すると見られる
  (各コマンドの mask 閾値ロジックは未追跡)。
- `req[6]`(1..0x19)は「要求アクセスレベル」で `0xFFD169` に控えられる。
- `0x3FFC`('M'/'S')は **Master/Slave 識別**。本イメージは master ⇒ `0x3FFC = 0x4D('M')`。
  Slave イメージ側は 'S' で早期 ack する。セキュリティとは無関係。

## cmd 0x90 ハンドラ @0x16B0 — 逐次(要約)

seed 生成ではなく、**プログラミングセッションの状態機械 + マジック文字列分岐**。

```
16B0 レジスタ退避、a5=&resp, a4=0xFFD0BA(作業バッファ)
     ; --- 分岐 A: "MSS52" マジック ---
16CE req[1]==0x09 && req[3..7]=="MSS52"(4D 53 53 35 32)?
1722   一致 → resp={01,A0,10}; pea #8; jsr $1b06 (0xFFD003 の bit3 をクリア); rts
     ; --- 分岐 B(不一致 = 0x174C): 状態機械 ---
174C 0xFFD164(セッション期限) と 0xFFE500(フリーランタイマ)を比較 → 期限切れなら jsr $1aea
1760 テーブル 0x5D17 を 9 バイト走査し「全 0xFF か」判定(本イメージは全 0xFF = 未書込)
1780 0xFFD004 & 0x0F を 3 と比較 / 0xFFD004 & 0x70 を 0x40/0x10/0x20 と比較(3 状態)
17D6 req[1]==8 && req[3..5]=="BMW"(42 4D 57)? → 分岐
18xx CRC/畳み込み風の計算で 0xFFD010 を作る(XOR 累積 + divs.l 剰余 + シフト)→ 応答詰め
```

- マジック **"MSS52"**(req に ASCII で乗せる)と **"BMW"** は、フラッシュ内の平文コード比較。
  いずれも「特定モード進入/ステータス取得」の合言葉で、**乱数応答ではない**。
- `0xFFD003 / 0xFFD004` は状態/フラグバイト。`0xFFD164` はセッション期限(タイマ比較でタイムアウト)。
- 18xx の計算は応答パケット(`0xFFD010`)を組む処理で、鍵検証ではない。

## cmd 0x9E / 0x9F / 0x12 — セッション補助(参考)

3 つとも同じ骨格:`0x3FFC` の M/S 識別 → Master なら `0xFFD007=7`、Slave なら早期 ack。加えて

- **0x9E** @0x15E8: `0xFFD00B = 0xFF`(coding フラグ)。
- **0x9F** @0x1624: `0xFFD168 = 0x3C`(モードマーク)、`0xFFD160 = 0xFFE500`(**タイマスナップショット**)。
- **0x12** @0x166A: `0xFFD168 = 0x33`、`0xFFD160 = 0xFFE500`(同上)。

`0xFFD168` は「プログラミングモードマーク」(cmd 0x34 が 0x36 を書くのと同族)。
`0xFFD160` はタイマのスナップショット。

## サブルーチン(参考)

| addr | 動作 |
|---|---|
| `0x1AEA` | `ori.b #$80, 0xFFD004`(bit7 セット = タイムアウト印) |
| `0x1AF4` | `0xFFD004` を `&0x8F` してから引数 bit を or(モード下位ニブル設定) |
| `0x1B06` | 引数 bit を **クリア**(`and (~arg)`)→ `0xFFD003` |
| `0x1B14` | 引数 bit を **セット**(`or arg`)→ `0xFFD003` |
| `0x1B20` | `0xFFD164 = 0xFFE500 + 0x2710`(セッション期限を +10000 tick 延長)、`0xFFD004` の bit7 クリア |

## ★ 「では WinKFP の乱数(seed)は何なのか」— レイヤの区別(重要・未確定を明記)

WinKFP の `AUTHENTISIERUNG_ZUFALLSZAHL_LESEN`(KWP2000 `$31/07`、Zufallszahl=乱数)と
`AUTHENTISIERUNG_START`(`$31/08`)は、**上で解いた DS2 の cmd 0x90/0x91 とは別レイヤ**である。

根拠(実測):
- DS2 コマンドテーブル(BL 0x37A2 / APP 0x3A1F0、計 26 コマンド)に **cmd 0x31 は存在しない**。
  KWP2000 の `$10/$11/$36/$37` も無い。⇒ WinKFP が送る KWP2000 SID 群は、この DS2 ディスパッチ表
  では処理されていない。
- 一方で cmd 0x34(=KWP `$34`)や cmd 0x06 は表にあり、BL のプログラミング経路と共有される。
- タイマスナップショット `0xFFD160`(cmd 0x9F/0x12 と、プログラミング状態機械 0x229E が書く)を
  **読む側**は 0x00C06 / 0x1B6A / 0x1C0A / 0x22A4 にあるが、いずれも**タイムアウト比較**であり、
  そこから鍵を導出して照合する箇所は見当たらない。⇒ `0xFFD160` は seed ではなく期限タイムスタンプ。

したがって:
- **DS2 レイヤのアクセス制御 = 固定パスワード(確定、上記)。**
- **KWP2000 プログラミングレイヤの `$31/07-08` auth = この表の外**。BL 内の KWP2000 プロトコル
  パーサ(`flash_req_parse` 近傍 0x289C〜のプログラミング状態機械)が処理していると見られるが、
  そこが「乱数を返し・計算応答を検証する本物の seed-key」なのか「固定パスワードを別 SID で受けて
  いるだけ」なのかは**未確定**(このファームで実装されているかも含め)。推測で埋めない。
