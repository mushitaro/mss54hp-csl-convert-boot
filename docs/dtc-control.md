# DTC の有効/無効はどう決まるか — 逆アセンブルで確定

「DTC オフ」は当初 UI に出さない方針だった。符号化が未確定だったからである。**確定した。**
根拠はファーム本体であり、純正データがそれを裏付けている。

## 1. 仕組み — CTL バイトのビット 0

DTC を上げる唯一の入口は `ed_report(error, errortype)` (master `0x033636` / slave `0x033386`)。
その冒頭に判定がある:

```c
/* ...because the control byte is the 13th byte the idea is that with the error * 0xe (14)
   you arrive at the control byte for the relevant error.
   In this case if the control byte is zero then we ignore the error and return */
if ((k_ed_fil_base[err].K_ED_FIL_CTL & 1) == 0) {
    return 0;
}
```

**CTL のビット 0 が 0 なら、その故障は数えられず、記憶されず、故障メモリに一切入らない。**
1 バイト・1 ビット。

レコードは 14 バイトで、フィールド名は XDF と逆コンパイルの構造体名が一致する:

| index | 名前 | 意味 |
|---|---|---|
| 0 | `DTC` | 故障コード (レコードの署名になる) |
| 1 | `SIN` | 故障確定のしきい値 |
| 2 | `SOUT` | 回復のしきい値 |
| 3–6 | `IN INC` / `OUT INC` / `IN DEC` / `OUT DEC` | デバウンス計数の増減量 |
| **12** | **`CTL`** | **bit0 = 有効。他ビットは OBD/MIL/フリーズフレームの扱い** |
| 13 | `TERM` | 終端 `0xFF` |

`ed_report` が使う他の CTL ビット: `0x04` (フリーズフレーム更新 `fsp_entry_update_art_and_ff` と
OBD ビット `0x0F`)、`0x10` (OBD ビットを `|1` にするか `|3` にするか)、`0x20` (OBD_STATE と
組み合わせて ART の `0x10` を立てる)。**無効化に要るのは bit0 だけ。**

## 2. BMW 自身がこの仕組みを使っている

純正 CSL 較正 `A7837331.0DA` (PD31) の 241 レコードを実読すると、**94 件が既に bit0 クリア**。
つまり出荷状態で無効な DTC が 4 割近くある。これは裏技ではなく設計された制御である。

## 3. アドレスは CSL 0401 でのみ有効 — 検証済み

XDF の DTC アドレスを SP-DATEN の MSS54HP 較正 46 本すべてに当て、レコード署名
(コードバイトと `TERM=0xFF`) が一致するか数えた:

| 較正 | slave 一致 | master 一致 | TERM=FF |
|---|---|---|---|
| **CSL (`PD*`) 6 本** | **121/121** | **120/120** | **241/241** |
| 標準 (24–25.02.03 群) 12 本 | 121/121 | **1/120** | 241/241 |
| 標準 (25.06.03 群) 以降 | **0/121** | 1/120 | 136/241 |

**CSL 0401 でだけ完全に一致する。** 標準較正は master 側の表が別の場所にあり、群によっては
slave 側も違う。したがって:

- 変種ビルダーは**書く前にレコード署名を検証する** (`assertDtcRecord`)。CSL 0401 でない較正を
  渡されたら、間違った場所に書かずに**拒否する**。
- 「標準 M3 の DTC 設定をコピーする」という手は**使えない**。

## 4. ⚠ 安全上の発見 — MAP の DTC を消すと**フォールバックまで消える**

`ed_report` の**戻り値**が健全性フラグとして使われている。`p_saug_no_filter_calc`
(master `0x01a8a4`):

```c
uVar1 = ed_report(DTC_DF_MAP_PRESSURE, errortype);
p_saug_ed = (byte)uVar1;
...
if (((UEXT1M_ED & 0x40) == 0) && ((p_saug_ed & 0x40) == 0)) {
    if ((p_saug_ed & 0x20) == 0) { p_saug_st = 0; }   /* MAP は「正常」 */
    else { p_saug_st = p_saug_st | 1; }
} else { p_saug_st = p_saug_st | 3; }
```

そして `rf_diag` (master `0x021b48`) が Alpha-N フォールバックを選ぶ条件:

```c
if ((p_saug_st & 2) != 0) {
    rf_diag_index_mask_raw = rf_diag_index_mask_raw & 0xfd;   /* MAP 使用可ビットを落とす */
}
rf_diag_ed_st = rf_diag_lut[...];
```

CTL bit0 を落とすと `ed_report` は **0** を返す → `p_saug_st` は 0 のまま → `rf_diag` は
**MAP が壊れていることを永久に知らない** → **フォールバックが選ばれない。**

> **結論**: 「MAP 経路を生かしたまま MAP の DTC だけ消す」は、**欠けたセンサーを無害にするので
> はなく、それを無害にしていた仕組みを外す**。クランプされただけの誤った値が充填計算に入り、
> それを咎めるものが無くなる。**この組み合わせはビルドしない。**

### さらに踏み込むと: **MAP の DTC は無効化してはいけない**

`rf_diag_lut` (master **`0x3D534`**、16 エントリ × 2 バイト `{ed_st, sk_st}`) をイメージから実読:

```
idx  0      1      2      3      4      5      6      7
    (1,2)  (1,2)  (2,2)  (2,2)  (1,2)  (1,2)  (2,1)  (0,1)
idx  8      9      10     11     12     13     14     15
    (1,2)  (1,2)  (2,1)  (0,1)  (1,0)  (1,0)  (2,1)  (0,0)
```

`rf_diag` が作るインデックスのビット: bit0 = LLS 健全 / **bit1 = MAP 健全** / bit2 = WDK2 /
bit3 = UEXT2・WDK1。そして `rf_calc` (master `0x0218d0`) は **`RF = rf_p_saug` を先に代入**し、
`rf_diag_ed_st` が **0**(k_rf_cfg が決める) か **1**(強制 Alpha-N) のときだけ上書きする。
**`ed_st == 2` のときは MAP 由来の値がそのまま残る** —— `k_rf_cfg` が何であっても。

MAP センサー未装着の車で追うと:

| | 挙動 |
|---|---|
| **DTC 有効** | MAP 診断が発火 → `p_saug_st` bit1 → インデックスの bit1 が落ちる → 残る全エントリ {0,1,4,5,8,9,12,13} が**すべて ed_st=1 = Alpha-N**。どの故障の組合せでも安全 |
| **DTC 無効** | `p_saug_st` は 0 のまま → bit1 が立ったまま。全健全 (idx 15) なら ed_st=0 で Alpha-N だが、**LLS 故障が 1 つ起きただけで idx 14 → ed_st=2 → RF = MAP 直値**。センサーが無ければ無意味な値が充填計算に入る |

⇒ **記憶される DTC は消すべきノイズではなく、全経路を Alpha-N に留める入力である。**
2 つ目の故障が静かに誤った燃料計算に化けるより、予期された DTC が出るほうがはるかに良い。

したがって MAP の選択肢:

| 選択 | `k_rf_cfg` | MAP DTC | |
|---|---|---|---|
| **使う** | `0x12` (純正) | **有効** | センサー有り前提 |
| **使わない / 後で使う** | **`0x02`** | **有効のまま** | DTC は出る。それが Alpha-N を保証する |
| ~~経路は生かして DTC だけ消す~~ | `0x12` | 無効 | ❌ フォールバックが消える |
| ~~Alpha-N にして DTC も消す~~ | `0x02` | 無効 | ❌ LLS 故障時に ed_st=2 で MAP 直値 |

**「後で使う」は「使わない」と同一イメージ**になる。ラベルも同じにしてある — バイトが同じなのに
ファイル名が違うのは、2 つのビルドを取り違える原因にしかならない。センサーを付けたら
「使う」で作り直す。

> **この節は当初の実装を訂正している。** セッション中、いったんは「Alpha-N にしたうえで MAP DTC
> も無効化する」を実装した。`rf_diag_lut` を実読して `ed_st=2` の経路が存在すると分かった時点で
> 撤回した。フラップ DTC の無効化は影響しない (`rf_diag` のインデックスにフラップは入らない)。

## 5. ⚠ 安全上の修正 — フラップ EGAS 表を 0 で埋めてはいけない

`kf_egas_wdk_ask` は**加算ではなく、フラップ開時に選ばれる置換表**(スロットル開度マップ)である
(`45-drivability-filters.md`)。実測:

| | 値域 | 備考 |
|---|---|---|
| `KF_EGAS_WDK` (通常) | 0–1000 | 最上行は 700–950 |
| `kf_egas_wdk_ask` (フラップ開) | 0–1000 | **322 セル中 4 セルしか違わない** |
| x 軸 | — | 1 点だけ違う (index 3: **1250 vs 1150 rpm**)、y 軸は同一 |

**0 で埋めると、フラップ開と判定された瞬間にスロットル開度 0 が指令される。**
しかもフラップ位置ポットが未装着で、そのうえ DTC を無効化していると、誤った ADC 値を
「正常」と信じるので、この判定は実際に起こり得る。

正しい「フラップ無し」処理は **通常表の x 軸と z データを ask 表にコピーする**こと。
そうすればどちらが選ばれても挙動は同じになる。これが「フラップは存在しない」の意味に一致する。

一方 `kf_rf_soll_ask` は**加算**なので、0 が正しい中立値。

## 6. 実装

`packages/dme-flash/src/variant.ts`:

- `DTC_RECORDS` — 4 レコードのアドレスとコード (`DF` MAP / `7C` POT / `1C` REGULATOR / `12` DRIVER)
- `assertDtcRecord` — コードバイトと `TERM=0xFF` を検証。CSL 0401 でなければ**拒否**
- `disableDtc` — CTL の bit0 だけを落とす (他ビットは触らない)
- `dtcEnabled` — UI が現状を表示するため
- `MAP_LATER_IS_OFF` — §4 の判断を型の隣に置き、テストが同一性を固定

純正 CSL の実値: MAP `0x03`、FLAP_POT `0x03`、FLAP_REGULATOR `0x03`、FLAP_DRIVER `0x01` —
いずれも bit0 が立っている。**無効化するのはフラップ 3 件だけ** (`0x02`/`0x02`/`0x00`)。
MAP の `0x03` は上記の理由で**そのまま残す**。
