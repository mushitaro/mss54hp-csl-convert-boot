# 自作 BDM ツール — 設計の見取り図

ブリックした DME を復旧するための BDM インターフェイスを自作する場合の設計。**未実装**。
仕様は `CPU32RM.pdf` §7 (Development Support)、物理タップ位置は YulCmr リポジトリの
`hardware_modifications/BDM.mkd` と `mounting/`。

## 1. なぜ既存資産がほぼそのまま乗るのか

**BDM はバイト列ではなくバスである。** DS2 は「ECU 自身のブートローダにフラッシュ操作を依頼する」
プロトコルなので `ByteTransport` (バイト列の往復) が正しい抽象だった。BDM は逆で、**こちらが
CPU を止めて、メモリ読み書きを直接発行する**。つまり必要な抽象は `readWord` / `writeWord` であり、
それは**エミュレータの `Bus` と同じ形**である (`emulator/cpu32.ts`)。

```
                    ┌─ Machine (エミュレータ)      ← オフライン検証
AmdFlashDriver ──►  │
  (新規)            └─ BdmLink ──► BdmWire ──► GPIO ← 実機
```

ここが設計上の最大の利点になる。**AMD のコマンドシーケンス (アンロック・消去・書込・DQ7/DQ5
ポーリング) をホスト側 TypeScript で書き、それを実機に繋ぐ前にエミュレータで走らせて検証できる。**
`flashAm29f400.ts` は BMW 自身のスタブを走らせて検証済み (`bmwStubs.test.ts`) なので、
そのモデルを相手に通るドライバは、既知の正解に照らして正しい。

BDM の**線の上のプロトコルだけ**は実機でしか検証できない。それ以外は全部オフラインで潰せる。

## 2. 新規モジュール 3 つ

| モジュール | 責務 | 検証方法 |
|---|---|---|
| `bdmWire.ts` | 17 ビット 1 語の全二重転送、BDM 有効化、FREEZE 監視 | 実機のみ |
| `bdmLink.ts` | `AsyncBus` の実装。READ/WRITE/DUMP/FILL を組み立てる | 語列を固定するユニットテスト |
| `amdFlashDriver.ts` | Am29F400 のコマンド列。消去・書込・ポーリング・照合 | **`Machine` 相手に完走** |

`AsyncBus` は `Bus` の非同期版として `emulator/cpu32.ts` の隣ではなく**パッケージ直下**に置く
(エミュレータ専用ではなくなるため)。`Machine` を包む同期→非同期アダプタを 1 つ書けば、
同じ `amdFlashDriver` が両方を駆動する。

## 3. 線の上のプロトコル (`CPU32RM.pdf` §7.2.7)

- **SPI 類似の全二重同期シリアル**。開発機側が DSCLK を生成するマスタ
- **1 語 17 ビット** = ステータス/制御ビット 1 + データ 16。**MSB first**
- データは **DSCLK の立ち下がりで遷移し、立ち上がりでラッチ**される
- 速度は **DC 〜 CPU クロックの 1/2**。MSS54HP は 20/25 MHz なので上限 10 MHz 前後だが、
  **下限が無い**。同期式なので遅い分には CPU が待つだけで、ジッタも害にならない

ピンは専用ではなく開発用ピンの兼用:

| BDM 時 | 通常時 | 向き (開発機から見て) |
|---|---|---|
| **DSCLK** | `BKPT` | 出力 |
| **DSI** | `IFETCH` | 出力 |
| **DSO** | `IPIPE` | 入力 |
| `FREEZE` | — | 入力 (BDM 中を示す) |
| `RESET` | — | 出力 (下記のとおり不要にできる) |

### 有効化

> BDM operation is enabled when BKPT is asserted (low), at the rising edge of RESET.
> BKPT must be held low for at least two clock cycles prior to negation of RESET.

**`RESET` を自分で駆動する必要は無い。** `BKPT` を Low に保ったまま **DME に電源を入れれば**、
リセットの立ち上がりはそこで起きる。DME 側のリセット IC と綱引きしなくて済む。YulCmr のピン一覧に
`VIN` があるのは、ツール側が DME の電源を握っている (または監視している) ためと思われる。

有効化後は `FREEZE` が Low→High になるのを待って確認する。

## 4. コマンド語 (`CPU32RM.pdf` §7.2.8)

サイズフィールドは byte=`00` / word=`01` / long=`10`。

| コマンド | ビット列 | 値 |
|---|---|---|
| `READ` | `0001 1001 SS 000000` | `0x1900 \| (size<<6)` |
| `WRITE` | `0001 1000 SS 000000` | `0x1800 \| (size<<6)` |
| `FILL` | `0001 1100 SS 000000` | `0x1C00 \| (size<<6)` |
| `DUMP` | — | **⚠ §7.2.8.10 から要抽出。** 上の 3 つとの対称性からは `0x1D00 \| (size<<6)` だが**推測は使わない** |
| `RSREG` | `0010 0100 1000 REG` | `0x2480 \| reg` |
| `RDREG`/`RAREG` | `0010 0001 1000 0 A/D REG` | `0x2180 \| (ad<<3) \| reg` |
| `WDREG`/`WAREG` | `0010 0000 1000 0 A/D REG` | `0x2080 \| (ad<<3) \| reg` |
| `GO` | `0000 1100 0000 0000` | `0x0C00` |
| `CALL` | `0000 1000 0000 0000` | `0x0800` |
| `RST` | `0000 0100 0000 0000` | `0x0400` |
| `NOP` | `0000 0000 0000 0000` | `0x0000` |

フラッシュを叩くのに必要なのは **`READ` / `WRITE` / `DUMP` / `FILL` の 4 つだけ**。`GO` や `CALL` は
使わない (CPU を走らせる必要が無い)。

**`DUMP` が速度を決める。** 初回 `READ` で開始アドレスを設定した後、後続は `DUMP` だけで
次の語が取れる。データ 1 語あたり概ね 2 転送 ≈ 34 クロック。**DSCLK 100 kHz でも 1 MiB が約 3 分**で、
YulCmr のツールの書込 2 分 45 秒と同じ土俵に乗る。速度を詰める理由が無い。

## 5. ハードウェア

### 電圧が唯一の実質的な障害

**MC68336 は 5V 部品で、入力しきい値は概ね 0.7×VDD = 3.5V。** 3.3V の GPIO では High を
確実に叩けない。

| | レベル変換 | 備考 |
|---|---|---|
| **Arduino (5V AVR、Uno/Nano)** | **不要** | 直結できる。RAM 2 KB なのでバッファせず流す構成 |
| **Raspberry Pi / STM32 (3.3V)** | **必要** | `74HCT244` / `74AHCT125` を **5V 電源**で挟む。HCT は TTL しきい値 (2.0V) なので 3.3V を High と認識し、出力は 5V |

**Pi を推す。** バッファ 1 個の手間で、**このリポジトリの TypeScript がそのまま Node で動く。**
検証済みのフラッシュロジック・CRC・セクタ地図を書き直さずに使えるほうが、部品 1 個より価値が大きい。

> ⚠ **ブリックしたフラッシュより悪い状態は、基板や CPU を電気的に壊すこと。** そうなると正しい
> BDM ツールを後から買っても復旧できない。3.3V 系なら必ずバッファを入れること。ここ以外に
> 慎重になる理由は無い。

### 配線

回路図が要らない規模。ブレッドボードで足りる。DME 側は **1.27mm ピッチ SMD 10 ピンヘッダ ×2**
(master / slave 各 1) の半田付けが要る。**これは買っても作っても同じく必要**で、arm する前に
済ませておくこと。

## 6. 作業順

1. **`bdmLink.ts` + `amdFlashDriver.ts` を先に書き、`Machine` 相手に完走させる。**
   ハードが 1 本も繋がっていない状態で、消去・書込・照合の全経路が通る
2. `bdmWire.ts` を書き、まず **`RSREG` でレジスタを 1 個読むだけ**を実機で通す。
   これが通れば線とレベルと 17 ビットの向きが正しいと分かる
3. `DUMP` で全域読み出し。**書き込みは一切せずに** 1 MiB を吸い、既存のバックアップと照合する。
   ここまで無リスク
4. 消去・書込は、その後
